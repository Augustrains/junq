# 攻击机返航奖励设计

## 目标

训练攻击机形成“成功发射武器 → 返航 → 抵达航母 → 完成补给”的闭环，同时阻止未执行武器投放的飞机为了领取返航奖励而盲目返航。

## 返航动作掩码

每架攻击机初始携带 1 枚 AAM（`fox3`）和 1 枚 AGM。只有该机至少成功发出过一种武器后，才开放 `RETURN_HOME`：

```python
return_available = aam_count < 1 or agm_count < 1
```

弹药在成功发送开火指令时减少。补给完成后弹药恢复为 1，返航动作重新锁定，直到下一架次再次发射武器。

- 编队长选择返航：所有存活编队成员收到返航指令。
- 僚机选择返航：只有该僚机返航。
- 被编队长带回、但没有发射武器的僚机可以执行返航，不过不获得返航阶段奖励。

## 奖励配置

配置位置：`envs/rewards/attack/rules.json` 的 `attack_return_rewards`。

| 奖励项 | 原始奖励 | 触发条件 |
|---|---:|---|
| 接近航母 | 每接近 10 km，`+0.5` | 本架次弹药减少，且处于 `returning` 状态 |
| 单步进度上限 | 50 km，即最多 `+2.5` | 防止位置跳变产生异常奖励 |
| 抵达航母 | `+6.0` | 从 `returning` 首次进入 `rearming` |
| 补给完成基础奖励 | `+8.0` | 收到 `attack_rearmed` 且实际补入弹药 |
| 每枚补入导弹 | `+4.0` | 按 `aam_loaded + agm_loaded` 计算 |

补给一枚的完成奖励为 `12.0`，补给两枚为 `16.0`。

攻击机局部奖励在共享训练奖励中乘以 `0.3`。例如补给两枚导弹的 `16.0` 原始奖励，对共享奖励的实际增量为 `4.8`。

## 防止错误奖励

- 没有任何弹药减少时，返航动作被掩码。
- 接近航母奖励只在正式进入 `returning` 状态后计算。
- 抵达奖励只结算状态转换，不会在补给等待期间重复发放。
- 补给奖励以 `attack_rearmed` 事件及实际装填数量为准。
- 编队奖励按飞机分别判断；未发射武器的僚机不会因被动随队返航获得奖励。

## 日志标识

训练信息的 `local_reward_details` 中会出现：

- `attack_return_carrier_progress`
- `attack_return_arrived_at_carrier`
- `attack_return_rearm_completed`
